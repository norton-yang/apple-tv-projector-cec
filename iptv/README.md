# 局域网精简 IPTV 订阅服务

软路由从用户自有上游订阅获取 M3U，筛选并重新分组，通过局域网 HTTP 地址交给 APTV。只处理列表，不代理视频，不扫描或检测播放地址，不需要 Home Assistant。

## 更新与限频

- 无缓存时启动后请求一次订阅地址，成功后每 **30 分钟**更新一次。重启时若缓存不足30分钟，先等待剩余时间，避免立即重复请求。
- 请求失败后等待 **5 分钟**重试，单次请求超时 35 秒。
- 单个后台线程顺序请求，没有应用层并发或立即重试。HTTP 跳转由标准客户端处理，可能增加实际 HTTP 请求数。
- APTV 请求本地列表只读取缓存，不触发上游更新。
- 更新失败保留上一次成功的列表，磁盘缓存可跨容器重启使用。
- 缓存已超过30分钟或缓存丢失时，重启会触发上游请求。
- APTV 的频道播放或预览会直接访问上游，不受本服务更新频率控制。上游断网时，缓存列表不代表视频仍能播放。

2026-10-24 实际部署代码与本目录 server.py 一致。配套 Dockerfile/Compose 用于重新部署，尚未在当前软路由构建验证；当前服务复用了已有 Home Assistant 镜像，执行的脚本仅使用 Python 标准库。

## 筛选规则

分组固定顺序：**上海 → 河南 → 央视 → 卫视**，组内维持原订阅顺序。

依赖此订阅的分组名称：

- `央视 · 主频` → 央视。
- `卫视 · 主频` → 卫视。
- `上海专区` → 上海；给部分通用频道名添加上海前缀。
- `河南专区` → 仅河南都市、河南民生、河南法治、河南电视剧、河南新闻、河南公共六个频道；河南卫视保留在卫视组。
- 不保留开封台及其他河南频道；重复编号线路合并，保留首条，不检测备用线路是否更优。
- 保留 M3U 头、台标、EPG 和其他原有频道属性；不适用于所有供应商格式。

按最新筛选规则，当前结果为央视18、卫视34、上海8、河南6，共66个频道；河南卫视包含在卫视组，数量可能随上游改变。

## 部署

1. 在此目录创建私有配置：

   ```sh
   mkdir -p data
   chmod 700 data
   cp config.example.json data/config.json
   chmod 600 data/config.json
   ```

2. 在 `data/config.json` 填入自己的订阅地址。不要提交配置或缓存。当前脚本固定监听 `192.168.0.2:8787`；其他机器请修改 server.py 末尾的地址，并确认端口空闲。
3. 启动：

   ```sh
   docker compose up -d --build
   docker logs --tail 20 iptv-local
   ```

4. APTV 添加：`http://192.168.0.2:8787/tv.m3u`（也支持 `/tv.m3u8`）。状态地址：`http://192.168.0.2:8787/status`。

不配置端口转发，仅在可信局域网使用。局域网内能访问该服务的设备可以读取含播放凭据的列表；不应通过公网反向代理发布。

## 实际运行位置与恢复

- 软路由目录：`/mnt/mmcblk0p4/Configs/iptv-local/`。
- 源码：`server.py`；私有订阅配置：`data/config.json`。
- 缓存：`data/tv.m3u`；状态：`data/status.json`。
- 容器名：`iptv-local`，重启策略 `unless-stopped`，日志轮转每份5MB、最多2份。
- 修改脚本后重启容器；检查 `/status` 和日志确认更新正常。
- 私有配置丢失时，重新填入自己的订阅地址即可；仓库故意不包含真实地址、账号或缓存。

```sh
docker restart iptv-local
docker stop iptv-local
docker update --restart=no iptv-local
```
